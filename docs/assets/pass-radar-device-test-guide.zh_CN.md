# pass-radar 双卡实测指南(说人话版)

> English: [pass-radar-device-test-guide.md](pass-radar-device-test-guide.md)
> 需要两张卡、大约 40 分钟,不需要任何特殊工具。
> 烧录的固件(一个文件,两张卡都烧它):`build/pass-radar_<版本>.bin`

## 一口气说清这次测什么

两张卡会互相"对话",然后告诉你**对方多远**、**在哪个方向**。这份指南就是
到真实环境里检查:这两个答案到底靠不靠谱 —— 室外、室内、拉远、以及把卡
绕着身体转一圈时的表现。

屏幕上会出现的三个词:

- **RSSI** —— 信号强度,好比"对面说话多大声"。越响越近。简单但粗糙。
- **FTM** —— 一只秒表,量无线电"打招呼"再回来花了多久。测距准得多,
  屏幕上出现 `FTM` 字样就是它在工作。
- **BLE** —— 第二条"慢但传得远"的无线电。第一条放弃时(太远),它还能
  勉强说一句"我还能看见你"。

## 准备(5 分钟)

1. 把**同一个**固件文件烧进**两张**卡:

   ```bash
   python -m esptool --chip esp32c3 -b 460800 -p 端口 write-flash 0x0 build/pass-radar_<版本>.bin
   ```

2. T1–T8 去开阔地(公园、空地);T9–T10 去有墙的房间。
3. 可选但有用:把一张卡插电脑,跑 `idf.py -p 端口 monitor` 看日志
   (下文引用的日志文案都来自这里)。

## 屏幕速查

| 屏幕显示 | 意思 | 问题 |
| --- | --- | --- |
| `DIST: 12.3 ±2 m [MED]` | 距离 12.3 米,老实告诉你误差 ±2 米,中等把握。`[HI]` 表示 ±0.5 米、很有把握。数字前有 `~` 表示"大概" | ± 无法正常显示，显示为一个框 |
| `RSSI:-58 FTM 2way [HI]` | 信号 -58,FTM 在工作,双向都测到了,高把握 | 看不到FTM字样，但显示有2way[MED] |
| `FAR NEAR (BLE)` / `FAR (BLE link)` | 普通无线电够不着了;长距慢速无线电还听得见(近档/远档) | 屏幕上看不到这些 |
| `OUT OF RANGE` | 两条无线电都失联 |  |
| `Angle: 187+/-9 deg` | 扫盘结果:方向 187°,两种测法差了 9°。`+/-` 越小越可信 |  |

## 测试项

### T1 — 冒烟(2 分钟,室内)

**做:** 两卡开机,相距 3–5 米,等 30 秒。
**过:** 第二行出现 `2way`;30 秒内出现 `FTM` 字样、把握升到 `[HI]`;
距离和真实差 ~2 米以内。
**记:** 显示距离 vs 真实距离。

### T2 — 标定一次(2 分钟,随地)

**做:** 两卡相距 1 米放稳,在主页**长按 OK**(任一张),保持 3 秒。
日志应出现 `标定完成`。
**过:** 提示出现;之后同一距离的读数更准一点。
**记:** 无——标定值断电也记得住。

### T3 — 室外距离阶梯(15 分钟)

**做:** 量出 1/3/5/8/12/20/30 米。每个点站定 20 秒读屏。
**过:** 出现 `FTM` 时误差 ≤2 米;数字不乱跳。
**记:** "真实距离 → 显示距离 → HI/MED" 表格。

### T4 — 室内距离阶梯(10 分钟)

**做:** 同样的阶梯,在走廊/有墙房间。
**过:** 不出离谱数字;把握降到 `[MED]` 属正常。
**记:** 同上表格;标出哪里变差。

### T5 — 定向扫盘,室外(10 分钟)

**做:** 朋友拿另一张卡站某方向。按 OK,用 4 秒原地转一整圈,读结果页。
8 个方向 × 2 轮。
注意:另一张卡会**自动跟着进入扫盘**(预期行为,不用管它);单人测试时
让它平放在桌上即可。
**过:** `Angle:` 与真实方向差 ≤±15°,每轮都算数。
**记:** 每一次的 `Angle: x+/-y deg`。

### T6 — 两张卡一起扫(5 分钟,v2.1 新增)

**做:** 两卡都在主页。在其中一张按 OK。盯着另一张。
**过:** 另一张**一秒内自己开始扫盘**(跟随)。两人都转;两张结果页
互相指向对方、角度大致镜像;`+/-` 分歧应比单卡独扫时更小。
**记:** 跟随是否启动、两个角度。

### T7 — 故意转太快(5 分钟,v2.1 新增)

**做:** 同一方向再扫一次——但 **3 秒就转完一圈**,然后保持不动等扫盘结束
(卡片仍会等满 4 秒)。
**过:** 箭头仍指向朋友(卡片会自己发现你提前转完了并修正换算)。日志出现
`sweep self-correction: duration 4000 -> ~3xxx ms`。没有这个修复时本测试
会偏 ~45°——这正是它要消灭的误差。
**记:** 修正后角度 vs 真实方向。

### T8 — 走远到 FAR(10 分钟,室外)

**做:** 盯着一张卡的主页,慢慢走远。
**过:** 先 `OUT OF RANGE`(普通无线电放弃);对方还在 50–100 米内时显示
`FAR NEAR (BLE)` 或 `FAR (BLE link)`;再走远到它也消失,回到
`OUT OF RANGE`。
**记:** 每次切换发生的距离——我们用这些数值调 NEAR/FAR 阈值。

### T9 — 藏起来的卡(5 分钟,v2.1 新增)

**做:** 把一张卡放兜里/藏背后 20–30 秒,相距约 5 米。
在另一张卡开**诊断页**(主页**连按两次 UP**;长按会被误读,别用长按)。
**过:** 第三行的 `env` 数字变成 `2`(遮挡);回到开阔处一分钟内变回
`0`/`1`。
**记:** 变化花了多久。

### T10 — 同一位置,两个页面(5 分钟,v2.1 新增)

**做:** 随便站哪。开诊断页(主页**连按两次 UP**),和主页对比。
**过:** 诊断页显示 `v1 <x> m | v2 <y> m` —— 老的简单办法 vs 新的融合办法。
`v2` 数字应与主页一致。
**记:** 挑 2–3 个位置把两个数都抄下来。这就是 v2 确实更强的 A/B 证据。

### T11 — 10 分钟连用(10 分钟)

**做:** 正常使用 10 分钟:追踪、扫几次盘、走近走远。
**过:** 不重启、不卡屏、屏幕不出乱码。
**记:** 任何异常。

### T12 — 和启动器和平共处(5 分钟)

**做:** 卡里装了 meta-pass 启动器的话:把本固件作为子固件安装并启动。
**过:** 雷达正常进入;**长按 OK 3 秒**返回启动器。
**记:** 过/不过。

## 出问题了?

- 完全没有 `FTM` → 检查**两张**卡都刷了新固件(旧 v1 能通话,但没有
  FTM/BLE 功能)。
- 距离系统性偏 → 先做 T2 标定,再重测。
- 日志里 `FTM session status=3` → 对端的 responder 没起来,两卡都重启。
- 室内扫盘指向乱 → 室内本来就更难;把 T5 的 `+/-` 值发给我们。
