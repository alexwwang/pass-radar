## ELI5 通俗摘要（先读这段）

新目标把"远距离也报一个准数"改成了"远距离报一个靠谱的范围"。**报范围也是本事**：设备必须知道"什么时候报数、什么时候报范围"——形式报错了，范围承诺也算不及格（降级输出计入分母）。

所以采集的目的变了：**不再是给距离公式调参（那部分收益已经很小），而是教设备"看情况换说法"**。要教这个，得在典型场景里各测若干次，让电脑总结"每种场景长什么样"。

**最小要采三样**：

1. **1 米标定**（几分钟，每次换设备/持握姿势做一次）——尺子归零，不做则点值全错；
2. **64 次分类采集**（8 种场景 × 2 个距离 × 4 次）——教设备认场景，这是新目标的核心数据；
3. **十几次带方位标注的扫盘**（顺带）——校正方向的固定偏差。

原计划的 78 次全矩阵 + 大验证集**不是取消，是推迟**：等真要对外承诺"已验证 80%"时再采。

## 1. 为什么新目标下采集可以缩减

按 80% 评审的定量结论，原采集矩阵各项对新目标的边际价值：

1. **P3/P4（n 与每环境参考）收益缩水**：中远距已改区间承诺（T3），n 的场地间波动（ln d 墙）任何拟合都消不掉；点值段只剩 3~15 m，n 用编译期值已把墙算进覆盖率。再按"每条件 ≥5 距离点"采满，只换来百分之几的点值提升；
2. **P5/P6（折点/远场）用不到**：新目标承诺只到 30 m，60/80/100 m 远场档纯为 P5/P6 服务，可整体推迟到 v3.1；
3. **P7/P8（降级判据）成为关键**：T3/T4 承诺的 80~90% 覆盖率是按"输出形式切换正确"推算的。出厂阈值是拍的——**这才是新目标下必须采集的部分**；
4. **D6 验证集只为"证明"存在**：不对外承诺就不采；分级承诺在文档上如实标注"设计预期，未验证"。

## 2. 与老方案的区别

| 维度 | 老方案（slot2 §3 统一矩阵 + 80% 评审 D6） | 最小方案（本文） | 区别原因 |
| --- | --- | --- | --- |
| 目标 | 拟合 P1~P10 全量参数 + 统计证明 80% | 标定降级判据（P7/P8）+ 零点标定复核（P1/P2/D1） | 新目标下点值段收窄，P3~P6 边际收益小 |

## 3. 最小采集集定义

### 3.1 C1：1 m 机内标定（P1/P2）——必做

- **时机**：每换设备对、或持握/放置姿态有变时，采前做一次；同姿态多天采集时每天复核一次；
- **做法**：现有 debug 标定会话（3 秒定时器，32 个 RSSI 样本 + 32 个 FTM 样本，写 NVS）；
- **记录**：记下 debug 页显示的 `tx_ref_sym` 与 `ftm_offset` 到采集记录表（固件侧日志见包 B2）；
- **重复**：同一姿态连做 3 次，偏差 >0.5 m（offset）或 >2 dB（ref）时停下来查环境。

### 3.2 C2：分类数据 64 run（P7/P8）——必做

- **构型**：8 个核心场景 × 2 个距离 × 4 次重复 = **64 run**（每类 ≥8 有效 run）；
- **距离**：室外 3 / 8 m；室内 3 / 6 m（场地允许 8 m 则用 8）；
- **顺序**：室内 4 场景先采（32 run），再室外 4 场景（32 run）；
- **每 run**：走现有 38 秒状态机（3 s 倒计时 + 5 s 稳定 + 30 s 采集）→ SAVE 入批次；**距离真值 = 所选整数档**（步幅摆位 + 摆位纪律，见 §6），标 `truth=paced`；
- **粗调档**：赶时间可先每场景 2 重复（32 run），但阈值结论只标 `PROVISIONAL`。

### 3.3 C3：方位标注 8~16 run（D1 偏置）——顺带

- 在 C2 的室外/室内 LOS run 中顺带挑 8~16 个，各做一次扫盘；
- 记录：屏显角度 + 真方位（8 方位中选 4~8 个方向，罗盘或场地参照物定真方位）+ sidecar 行；
- 用途：`sweep_bias_deg` 环形中值估计（16 run → CI ≈ ±5°；8 run → ±8°）。

### 3.4 明确推迟项

| 推迟项 | 原计划位置 | 恢复时点 |
| --- | --- | --- |
| P3/P4 正式拟合（每条件 ≥5 距离点） | slot2 §3 扩展档 | 需要点值承诺覆盖 20 m 以外时 |
| P5/P6 远场（60/80/100 m） | slot2 §3.1 远场扩展档 | v3.1 远距阶段 |
| D6 验证集（每场景 ≥65/30 run） | 80% 评审 §8.1 | 对外承诺"已验证 80%"之前 |
| P10 卡尔曼网格重放 | 更新程序 §4.4 | 动态场景 T4 表现不达标时 |

## 5. 所需变动的实施方案

### 5.1 包 A：操作与 PC 工具（不改固件）

| 项 | 内容 | 工作量 | 验收 |
| --- | --- | --- | --- |
| A1 sidecar 模板与操作清单 | YAML 模板（batch/run/measured_distance_m/bearing_deg/window_ms，格式见更新程序 §6.3）+ §6 操作员清单；日常只记方位，距离默认整数档，D6 才记实测 | 文档级 | 试填 3 行无歧义 |
| A2 `model_fit.py parse/report` 最小子集 | 解析 BATCH_*/CAPTURE/CSV 行 + `SWEEP_RESULT` + sidecar 合并（`DISTANCE_SIDECAR_*` 校验）；输出每 run 一行质量表（对账/CRC/标签/真值到位） | Python 约 400~600 行 | 对仓库已有测试批次日志跑通，run 表完整、SUSPECT 判定正确 |
| A3 `features.py` 特征重放 | `radar_obstruct.c`/`radar_fusion.c` 分类特征纯 numpy 移植 + C/Python 对拍测试（同输入输出差 ≤1e-4） | Python 约 300 行 + host 对拍 | 对拍测试全绿 |

### 5.2 包 B：固件最小变更（约 3 行 + 可选 3 行）

| 项 | 内容 | 必要性 | 验收 |
| --- | --- | --- | --- |
| B1 `SWEEP_RESULT` 日志 | `sweep_done` 尾部（共识融合后）加一行 `ESP_LOGI(TAG, "SWEEP_RESULT angle=%.1f spread=%.1f dist=%.2f conf=%d", …)` | **必做**（D1 依赖） | 真机一次扫盘后 USB 日志出现该行；host 全套回归 |

### 5.3 包 C：延后包（v5 剩余，非最小集必需）

probe/regular 分离、run baseline、聚合容量 32 + `OVERFLOW`、observed run 级众数、canonical CRC、provenance 补强（定义均已冻结于补救设计 R-01~R-11）。

**实施时点**：严格 P1/P2 重拟合之前，或对外发布"已验证 80%"声明之前。

## 6. 操作员执行清单

```text
每设备对开始前：
  1. 1 m 标定 ×3，记录 ref / offset（偏差过大停下检查）
每 run：
  2. 步幅摆位到选定距离档（摆不到位就重摆或改档；1 m 标定用参照物，勿用步幅）
  3. Capture 编辑页选场景（8 选 1）与距离档 → START
  4. 等 38 s 自动 SAVE，记 run 号
  5. 在 sidecar 记一行：run 号 / 实测距离 / 时间窗
方位 run（C3，8~16 个）：
  6. 选定真方位（罗盘/参照物）→ 做扫盘 → 记屏显角 + 真方位
批次收尾：
  7. 长按 DOWN 导出 → 跑 parse/report
  8. SUSPECT run 当场补采；每类凑满 8 个有效 run
```

## 7. 验收标准

1. `report` 中 64 run 全部 VALID（SUSPECT ≤10% 且已补采补齐）；
2. 每类 ≥8 有效 run，混淆矩阵出基线 macro-F1（作为 P7/P8 阈值拟合输入）；
3. D1 偏置估计：16 run 时 CI ≤ ±5°，8 run 时 ≤ ±8°；
4. 1 m 标定 3 次重复性：offset 极差 ≤0.5 m、ref 极差 ≤2 dB；
5. 粗调档（32 run）产出的阈值一律标 `PROVISIONAL`，不进参数包。

## 8. 风险与边界

- **不采远场** → P5/P6 保持编译期值；新目标 30 m 内承诺不受影响，45 m 以外仍是区间/档位；
- **不采验证集** → 80% 是设计预期而非统计证明；对外文案必须如实表述，不得写"已验证"；
- **真值为步幅级**（`truth=paced`，±3~8%）→ P7/P8 拟合不受实质影响（分类不减距离真值；P7 误差评估略偏保守）；但 D6 对外验证必须换验证级真值（卷尺/激光/场地标定物），否则 20% 判据的验收结论不可信；
- **ftm_raw probe 混合**（v4）→ P1 复算只作合理性检查，不产出新 offset（严格版等包 C）;
- **粗调档结论**只能用于内部迭代，任何对外承诺必须基于 64 run 正式档；
- 若某类场景（如 I-MULTIPATH）在 4 次重复后特征仍高度混杂，如实标"特征不足"并提出新增特征需求（更新程序 §4.3.1 规则 4），不硬凑阈值。
